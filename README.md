# PLCJS_ETH_MODULE_4RTD_D4MG_STM32F407VGT6

Прошивка Ethernet-модуля PLCJS с 4 аналоговыми входами термосопротивлений
(RTD) на базе `STM32F407VGT6`.

Модуль измеряет 4 канала RTD через изолированные АЦП `MAX31865` (SPI),
конвертирует сопротивление в температуру по выбранной шкале (ГОСТ 6651 /
IEC 60751 / DIN 43760), публикует показания по `Modbus TCP`, хранит настройки
во внутренней Flash, а калибровку — в отдельном одноразово записываемом
(write-once) секторе Flash, управляет главным индикатором `STAT_LED` и
четырьмя канальными светодиодами, поддерживает factory reset и программный
переход в Ethernet bootloader для OTA-обновления.

MAC-адрес уникален для каждого изделия: он детерминированно выводится из
96-битного уникального ID кристалла `STM32` (не хранится и не требует
провизионинга), поэтому в приложении и в bootloader он совпадает автоматически.

Базовая архитектура (сеть, Modbus TCP сервер, настройки во Flash, LED,
bootloader/OTA) унаследована от варианта `12DI`; аналоговая часть добавлена
заново.

## Аппаратная платформа

| Узел | Описание |
|---|---|
| MCU | `STM32F407VGT6`, Cortex-M4F |
| Ethernet | `KSZ8863` switch/PHY, RMII |
| АЦП RTD | 4× `MAX31865`, гальванически изолированы (ADuM5000 + ADuM1400/1311) |
| Подключение датчиков | 3-проводная схема (2-проводная — физической перемычкой) |
| Переключение диапазонов | аналоговый ключ `ADG849` на канал (смена опорного резистора) |
| Температура MCU | внутренний датчик (`ADC1_IN16`) |
| Factory reset | кнопка `FACT_RES`, active-low (также подтверждает аварийный сброс калибровки) |
| Индикация | `STAT_LED` + 4 канальных светодиода |
| Watchdog | `IWDG` |

### Распиновка аналоговой части

| Сигнал | Пин | Сигнал | Пин |
|---|---|---|---|
| SPI1 SCLK | PA5 | SPI1 MISO | PA6 |
| SPI1 MOSI | PB5 | | |
| RTD0_CS | PD13 | RTD0_RANG | PD10 |
| RTD1_CS | PD9  | RTD1_RANG | PD8 |
| RTD2_CS | PB15 | RTD2_RANG | PB14 |
| RTD3_CS | PB10 | RTD3_RANG | PE15 |
| RTD0_STAT | PE14 | RTD1_STAT | PE13 |
| RTD2_STAT | PE12 | RTD3_STAT | PE11 |

SPI: master, 8-бит, MSB first, **mode 3 (CPOL=1, CPHA=1)**, ~2.6 МГц
(PCLK2/32). Все `MAX31865` настроены на 3-проводный режим, непрерывное
преобразование, VBIAS включён, фильтр 50 Гц.

### Канальные светодиоды

- **горит постоянно** — канал активирован (`enabled = 1`), нет ошибки;
- **не горит** — канал деактивирован;
- **быстро мигает (5 Гц)** — ошибка АЦП (fault от MAX31865).

## Шкалы термосопротивлений и коэффициент α

Поддерживаемые типы (имя кодирует материал и стандартный α; W100 = R100/R0):

| Тип | Материал / стандарт | α | W100 по умолч. |
|---|---|---|---|
| `50М/100М/500М/1000М` | медь, ГОСТ | 0.00428 | 1.4280 |
| `Cu50/Cu100/Cu500/Cu1000` | медь | 0.00426 | 1.4260 |
| `50П/100П/500П/1000П` | платина, ГОСТ | 0.00391 | 1.3910 |
| `Pt50/Pt100/Pt500/Pt1000` | платина, IEC 60751 | 0.00385 | 1.3851 |
| `Ni100/Ni500/Ni1000` | никель, DIN 43760 | 0.00617 | 1.6180 |
| `0…2 кОм`, `0…5 кОм` | режим сопротивления | — | — |

Организация выбора **тип + α** на уровне пользователя (по ModbusTCP):

1. **Тип датчика** (`sensor_type`) — задаёт материал, R0 и стандартный α;
2. **Режим α** (`alpha_mode`): `0` — стандартный α по типу (ГОСТ/IEC/DIN),
   `1` — пользовательский;
3. **Custom W100** (`W100 × 10000`, напр. `13851`) — применяется при
   `alpha_mode = 1`. Позволяет подстроиться под конкретного производителя.

Платина считается по уравнению Каллендара–Ван Дюзена в форме (α, δ, β): при
пользовательском W100 меняется только α, а δ/β остаются стандартными. Медь —
линейно с малой поправкой ниже 0 °C. Никель — полином DIN, масштабируемый по
α. Обратная функция T(R) — численно (бисекция). Режимы сопротивления
возвращают Ω напрямую (температура = NaN).

## Диапазоны и опорные резисторы

На каждом канале ключ `ADG849` (сигнал `RANG`) выбирает один из двух опорных
резисторов:

| Диапазон | RREF ном. | Резисторы платы | Датчики |
|---|---|---|---|
| low  | ~400 Ω  | 2×200 (±0.1 %) | 50 / 100 Ω |
| high | ~4000 Ω | 2×2k (±0.1 %)  | 500 / 1000 Ω, 0…2 кОм, 0…5 кОм |

Диапазон выбирается автоматически по типу датчика (`rtd_type_range`). Пин
`RANG` устанавливается в `rtd_module_apply_config()`. Полярность задаётся
константой `RTD_RANG_LEVEL_HIGH` в `rtd_module.c` — если показания окажутся
в ~10 раз мимо, достаточно инвертировать её.

## Калибровка (0.2 %)

В цепи опорного резистора есть паразитное Ron ключа `ADG849` и допуск RREF
`±0.1 %`. Поэтому каждый канал калибруется отдельно для каждого диапазона по
2-точечной (или многоточечной) линейной модели:

```
R_true = gain × R_raw + offset
```

где `R_raw = code/32768 × RREF_ном`. `gain` убирает ошибку RREF, `offset` —
Ron ключа. Коэффициенты хранятся per channel × per range.

Калибровка выполняется поверенным магазином сопротивлений **АКИП-2202А
(0.05 %)** по Modbus TCP с помощью инструмента в `tools/` (Node.js или
Python, диалоговый режим). Подробности — в [tools/README.md](tools/README.md).

### Одноразовая запись (write-once)

Калибровка хранится в отдельном секторе Flash (sector 11), который прошивка
**никогда не стирает** в обычной работе — она переживает factory reset. Каждый
из 8 слотов (4 канала × 2 диапазона) можно зафиксировать (commit) **ровно один
раз**; после этого перезапись отклоняется. Порядок:

1. записать `gain`/`offset` в регистры `540+` — это живой предпросмотр
   (влияет на показания сразу, но не сохраняется);
2. записать `0xCA00 | (ch×2 + range)` в регистр `131` (**CAL COMMIT**) — слот
   программируется во Flash и блокируется. Значения `slot`: `0` = CH0 low,
   `1` = CH0 high, `2` = CH1 low, … `7` = CH3 high;
3. статус блокировок — input-регистр `127` (битовая маска, бит `ch×2+range`).

Попытка записи в `540+` или повторного commit для уже заблокированного слота
возвращает Modbus-исключение `ILLEGAL DATA VALUE`.

### Аварийный сброс калибровки (двухфакторный)

Ошибочно откалиброванное изделие можно разблокировать, но только при
**физическом присутствии** (по сети в одиночку — нельзя):

1. записать `0xC1A5` в регистр `132` (**CAL ERASE ARM**) — взводит окно 30 с;
2. в течение окна удержать кнопку `FACT_RES` ~3 с.

Тогда сектор калибровки стирается (все слоты → `gain=1.0, offset=0.0`,
разблокированы), и модуль перезагружается. Во время взвода `STAT_LED` мигает
частым 5-импульсным поездом; перед перезагрузкой — быстрым равномерным
миганием. Одного взвода по сети или одного нажатия кнопки недостаточно.

## Карта регистров Modbus

Числа с плавающей точкой — IEEE-754 float32 в двух регистрах, **старшее слово
первым** (big-endian word order).

### Показания — Input Registers (FC04), с 300

На канал, база `300 + ch×20` (ch = 0..3):

| Смещение | Тип | Описание |
|---|---|---|
| +0..1 | float32 | температура, °C (NaN для режима сопротивления/ошибки) |
| +2..3 | float32 | калиброванное сопротивление, Ω |
| +4..5 | float32 | «сырое» сопротивление, Ω (вход калибровки) |
| +6 | u16 | флаги: bit0 enabled, bit1 valid, bit2 fault, bits15..8 = fault-статус MAX31865 |
| +7 | u16 | 15-битный код АЦП |
| +8 | u16 | текущий диапазон (0 = low, 1 = high) |

Каналы: CH0 = 300, CH1 = 320, CH2 = 340, CH3 = 360.

Глобальные: `120` fw major, `121` fw minor, `122/123` uptime (с), `125`
module id (`0x04D1`), `126` температура MCU (signed 0.1 °C), `127` битовая
маска блокировки калибровки (бит `ch×2+range` = слот зафиксирован).

### Конфигурация — Holding Registers (FC03/06/16), с 500

Общие:

| Рег | Описание |
|---|---|
| 100 | период опроса RTD, мс (50..5000) |
| 101 | режим LED (0/1/2) |
| 102 | Modbus slave id | 103 | Modbus TCP порт |
| 104..107 | static IP | 108..111 | netmask | 112..115 | gateway |
| 116 | net mode: `0` static / `1` DHCP / `2` link-local (default `2`) |
| 117 | SAVE (`0xA5A5`) | 118 | REBOOT (`0xB00B`) / BOOTLOADER (`0xB007`) / сброс KSZ8863 (`0x8863`) |
| 119 | FACTORY RESET (`0xDEAD`) | 130 | температура MCU (RO) |
| 131 | CAL COMMIT (`0xCA00 \| slot`, slot 0..7) — фиксация калибровки |
| 132 | CAL ERASE ARM (`0xC1A5`) — взвод аварийного сброса калибровки |

На канал, база `500 + ch×10`:

| Смещение | Описание |
|---|---|
| +0 | enabled (0/1) |
| +1 | тип датчика (`rtd_type_t`, 0..20) |
| +2 | режим α (0 = стандартный, 1 = custom) |
| +3 | custom W100 × 10000 |
| +4 | форс диапазона для калибровки (0 = авто, 1 = low, 2 = high; runtime) |
| +5 | сглаживание (0 = выкл, 1 = слабое, 2 = среднее, 3 = сильное), см. раздел «Программное сглаживание» |

Коэффициенты калибровки (float32), база `540 + ch×8` (**write-once**, см.
раздел «Калибровка»):

| Смещение | Описание |
|---|---|
| +0..1 | gain, диапазон low | +2..3 | offset, диапазон low |
| +4..5 | gain, диапазон high | +6..7 | offset, диапазон high |

Запись в эти регистры — живой предпросмотр; фиксация во Flash выполняется
записью `0xCA00 | (ch×2+range)` в регистр `131`. После фиксации слот
блокируется (см. регистр `127` и раздел «Аварийный сброс калибровки»).

Номинальные опорные резисторы (float32, Ω): `580..581` RREF low,
`582..583` RREF high.

## Программное сглаживание показаний

Помимо аппаратного notch-фильтра 50 Гц в `MAX31865`, прошивка имеет
поканальный программный фильтр — экспоненциальное сглаживание (EMA),
включаемый регистром `500 + ch×10 + 5`:

| Значение | Режим | Коэффициент α |
|---|---|---|
| 0 | выключено (по умолчанию) | — |
| 1 | слабое | 1/4 |
| 2 | среднее | 1/8 |
| 3 | сильное | 1/16 |

Фильтр применяется к калиброванному сопротивлению перед преобразованием в
температуру: `R = R + α·(R_изм − R)`. «Сырое» сопротивление (+4..5) и код АЦП
(+7) не фильтруются — по ним всегда видно нефильтрованный сигнал.

Фильтр автоматически перезапускается (заполняется первым же достоверным
отсчётом, без «доезда» от старого значения) после ошибки датчика, смены
диапазона/типа и любого изменения конфигурации канала.

**Важно: при включённом сглаживании период оцифровки аналогового сигнала
(регистр `100`) не равен времени установления показаний.** Каждый цикл опроса
показание обновляется, но после скачка измеряемой величины оно приближается к
новому значению экспоненциально. Ожидаемое время установления показания RTD:

```
t_уст(63 %) ≈ T_скан / α
t_уст(95 %) ≈ 3 · T_скан / α
```

где `T_скан` — период опроса (регистр `100`, мс), `α` — коэффициент из таблицы.

Примеры при `T_скан = 250 мс` (по умолчанию):

| Режим | α | t_уст(63 %) | t_уст(95 %) |
|---|---|---|---|
| слабое | 1/4 | ~1 с | ~3 с |
| среднее | 1/8 | ~2 с | ~6 с |
| сильное | 1/16 | ~4 с | ~12 с |

Увеличение периода опроса пропорционально растягивает время установления:
при `T_скан = 1000 мс` и сильном сглаживании `t_уст(95 %) ≈ 48 с`.
Настройка сохраняется по триггеру SAVE (регистр `117`) вместе с остальной
конфигурацией.

## Flash layout

Приложение собирается как образ для работы с bootloader.

| Область | Адрес | Размер | Назначение |
|---|---:|---:|---|
| Bootloader | `0x08000000` | 128 KB | sectors 0-4 |
| Metadata | `0x08020000` | 128 KB | sector 5 |
| Application | `0x08040000` | 256 KB | sectors 6-7 (эта прошивка) |
| Staging | `0x08080000` | 256 KB | sectors 8-9 |
| Settings | `0x080C0000` | 128 KB | sector 10 |
| Calibration | `0x080E0000` | 128 KB | sector 11 (write-once, не стирается) |

Настройки защищены CRC32; при несовпадении magic/version/CRC загружаются
дефолты. `SETTINGS_MAGIC = 0x04D14A57`, `SETTINGS_VERSION = 2` (калибровка
вынесена из структуры настроек в отдельный сектор).

Калибровка хранится в секторе 11 как 8 CRC-защищённых слотов (`ch×2+range`);
сектор стирается только аварийным сбросом (см. «Калибровка»). Пустой слот
даёт нейтральные коэффициенты `gain=1.0, offset=0.0`.

## Сборка

Требуется STM32CubeCLT (`starm-clang`, `cmake`, `ninja`).

```powershell
cmake -S . -B build/Debug -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  -DCMAKE_TOOLCHAIN_FILE=cmake/starm-clang.cmake
cmake --build build/Debug
```

Идентичность варианта — единый источник `Application/fw_header/fw_header.h`:
`FW_PRODUCT_ID=0x504C0403`, `FW_HW_REVISION=0x0101`, `FW_VERSION_VALUE=0x0109`
(при необходимости переопределяются через `-DFW_PRODUCT_ID=...` и т.д.).

Результаты: `.elf`, `.hex`, `.bin` в `build/Debug/`. `.bin` — OTA-образ с
`fw_header_t` по смещению `0x200`.

## Прошивка

```powershell
STM32_Programmer_CLI -c port=SWD -w build/Debug/PLCJS_ETH_MODULE_4RTD_D4MG_STM32F407VGT6.elf -v -rst
```

## Сеть (дефолты)

| Параметр | Значение |
|---|---|
| Сетевой режим (`USE_DHCP`) | `2` = link-local (заводской) |
| Заводской адрес | `169.254.<mac[4]>.<mac[5]>` /16, из UID |

Из коробки — AutoIP link-local `169.254.x.y` (находится по MAC через discovery, вкладка «Обнаружение» в ModbusTool, UDP-broadcast порт `20556`). ## Примечания по точности

- Диапазон high (`RREF≈4 кОм`) уверенно перекрывает 0…2 кОм; шкала 0…5 кОм
  измеряется до ~4 кОм (ограничение опорного резистора платы).
- У `MAX31865` нет доступного по SPI датчика температуры кристалла, поэтому
  «встроенная температура АЦП» не выводится; доступна температура MCU
  (`ADC1_IN16`, рег. 126/130).
