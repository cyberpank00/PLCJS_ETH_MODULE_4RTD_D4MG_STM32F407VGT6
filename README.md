# PLCJS_ETH_MODULE_4RTD_D4MG_STM32F407VGT6

Прошивка Ethernet-модуля PLCJS с 4 аналоговыми входами термосопротивлений
(RTD) на базе `STM32F407VGT6`. **Плата HW2.1** (АЦП `ADS1220`).

Модуль измеряет 4 канала RTD через изолированные 24-битные АЦП `ADS1220`
(SPI, по одному на канал), конвертирует сопротивление в температуру по
выбранной шкале (ГОСТ 6651 / IEC 60751 / DIN 43760), публикует показания по
`Modbus TCP`, хранит настройки во внутренней Flash, а калибровку — в отдельном
одноразово записываемом (write-once) секторе Flash, управляет главным
индикатором `STAT_LED` и четырьмя канальными светодиодами, поддерживает factory
reset и программный переход в Ethernet bootloader для OTA-обновления.

MAC-адрес уникален для каждого изделия: он детерминированно выводится из
96-битного уникального ID кристалла `STM32` (не хранится и не требует
провизионинга), поэтому в приложении и в bootloader он совпадает автоматически.

Базовая архитектура (сеть, Modbus TCP сервер, настройки во Flash, LED,
bootloader/OTA) унаследована от варианта `12DI`. Прошивка для плат HW1.x
(`MAX31865` + ключ `ADG849`) зафиксирована тегом `hw1.1-last`.

## Аппаратная платформа

| Узел | Описание |
|---|---|
| MCU | `STM32F407VGT6`, Cortex-M4F |
| Ethernet | `KSZ8863` switch/PHY, RMII |
| АЦП RTD | 4× `ADS1220` (24 бит, Δ-Σ, PGA, 2 источника тока), гальванически изолированы |
| Подключение датчиков | 3-проводная схема, компенсация проводов двумя согласованными токами |
| Диапазон измерения | выбирается усилением PGA (без внешних ключей) |
| Опорный резистор | 2 кОм ±0.1 % в цепи возврата токов (ратиометрическое измерение) |
| Температура MCU | внутренний датчик (`ADC1_IN16`) |
| Factory reset | кнопка `FACT_RES`, active-low (также подтверждает аварийный сброс калибровки) |
| Индикация | `STAT_LED` + 4 канальных светодиода |
| Watchdog | `IWDG` |

### Распиновка (HW2.1)

| Сигнал | Пин | Сигнал | Пин |
|---|---|---|---|
| SPI1 SCLK | PA5 | SPI1 MISO | PA6 |
| SPI1 MOSI | PB5 | | |
| RTD0_CS | PC6  | RTD1_CS | PD15 |
| RTD2_CS | PD14 | RTD3_CS | PD13 |
| RTD0_STAT | PE14 | RTD1_STAT | PE13 |
| RTD2_STAT | PE12 | RTD3_STAT | PE11 |
| STAT_LED | PE9 | FACT_RES | PE10 |
| ETHRST | PD11 | ETHINT | PB1 |

SPI: master, 8-бит, MSB first, **mode 1 (CPOL=0, CPHA=1)**, ~2.6 МГц
(PCLK2/32). Сигнал `DRDY` не разведён — данные читаются командой `RDATA` из
задачи опроса.

### Схема канала и конфигурация ADS1220

```
S+ ── AIN2 (IDAC1)  и через 10k ── AIN0 (AINP)
S- ── AIN3 (IDAC2)  и через 10k ── AIN1 (AINN)
E  ── RREF 2k ── GND ;  REFP0/REFN0 — с концов RREF
```

| Регистр | Значение | Поля |
|---|---|---|
| 0 | `gain<<1` | MUX AIN0/AIN1, GAIN по классу, PGA включён |
| 1 | `0x04` | 20 SPS, normal, **непрерывное преобразование** |
| 2 | `0x55` | внешняя опора REFP0/REFN0, FIR 50+60 Гц, **IDAC 500 мкА** |
| 3 | `0x70` | IDAC1 → AIN2, IDAC2 → AIN3 |

Оба тока возвращаются через `RREF`, поэтому `V_REF = 2·I·RREF = 2.0 В`, а
дифференциальный вход равен `I·R_RTD` (сопротивления проводов S+/S-
компенсируются при `I1 = I2`):

```
R_RTD = code / 2^23 × 2·RREF / gain
```

Ошибка источников тока при этом сокращается; остаются допуск `RREF` и ошибка
усиления PGA, которые убирает калибровка.

### Канальные светодиоды

- **горит постоянно** — канал активирован (`enabled = 1`), нет ошибки;
- **не горит** — канал деактивирован;
- **плавно разгорается и гаснет за 2 с, затем 0.5 с пауза (цикл 2.5 с)** — ошибка (обрыв/КЗ/обратное включение датчика, АЦП не отвечает).

Заводские настройки каналов: все четыре **включены**, тип **Pt1000**.

## Шкалы термосопротивлений и коэффициент α

Поддерживаемые типы (имя кодирует материал и стандартный α; W100 = R100/R0):

| Код | Тип | Материал / стандарт | α | W100 по умолч. |
|---|---|---|---|---|
| 0/5/10/15 | `50М/100М/500М/1000М` | медь, ГОСТ | 0.00428 | 1.4280 |
| 1/6/11/16 | `Cu50/Cu100/Cu500/Cu1000` | медь | 0.00426 | 1.4260 |
| 2/7/12/17 | `50П/100П/500П/1000П` | платина, ГОСТ | 0.00391 | 1.3910 |
| 3/8/13/18 | `Pt50/Pt100/Pt500/Pt1000` | платина, IEC 60751 | 0.00385 | 1.3851 |
| 4/9/14 | `Ni100/Ni500/Ni1000` | никель, DIN 43760 | 0.00617 | 1.6180 |
| 19 | `0…200 Ом` | режим сопротивления | — | — |
| 20 | `0…2000 Ом` | режим сопротивления | — | — |

Организация выбора **тип + α** на уровне пользователя (по Modbus TCP):

1. **Тип датчика** (`sensor_type`) — задаёт материал, R0 и стандартный α;
2. **Режим α** (`alpha_mode`): `0` — стандартный α по типу (ГОСТ/IEC/DIN),
   `1` — пользовательский;
3. **Custom W100** (`W100 × 10000`, напр. `13851`) — применяется при
   `alpha_mode = 1`. Позволяет подстроиться под конкретного производителя.

Платина считается по уравнению Каллендара–Ван Дюзена в форме (α, δ, β): при
пользовательском W100 меняется только α, а δ/β остаются стандартными. Медь —
линейно с малой поправкой ниже 0 °C. Никель — полином DIN, масштабируемый по
α. Обратная функция T(R) — численно (бисекция). Режимы сопротивления
возвращают Ω напрямую (температура = NaN).

## Классы усиления (диапазоны)

Диапазон измерения задаётся усилением PGA `ADS1220`. Каждый тип датчика
принадлежит одному из пяти классов; класс выбирается автоматически по типу
(`rtd_type_gclass`) либо принудительно регистром `20..23` (для калибровки).
Полная шкала `FS = 4000 Ом / gain`.

| Класс | Gain | FS | Типы |
|---|---|---|---|
| 0 | 16 | 250 Ом | 50М, Cu50, 50П, Pt50 |
| 1 | 8 | 500 Ом | Ni100, 100М, Cu100, 100П, Pt100, `0…200 Ом` |
| 2 | 2 | 2000 Ом | Ni500, 500М, Cu500, 500П, Pt500 |
| 3 | 1 | 4000 Ом | Ni1000, 1000М, Cu1000, 1000П, Pt1000 |
| 4 | 1 | 4000 Ом | `0…2000 Ом` |

Таблица усилений — `s_gclass[]` в `rtd_scales.c`. Pt500 при 850 °C
(1953 Ом) занимает 97.6 % шкалы класса 2.

### Детекция ошибок датчика

У `ADS1220` нет регистра ошибок; состояние определяется по коду:

| Код ошибки (флаги, биты 15..8) | Условие |
|---|---|
| 1 — обрыв / превышение | **контроль петли возбуждения**: раз в ~4 с канал на один скан переключается в монитор `(REFP0−REFN0)/4`; если ток через RREF не течёт (`V_REF` < 20 % номинала) — обрыв, независимо от кода АЦП и усиления. Дополнительно `code ≥ 0x7FF000` (насыщение). Во время проверки и ~1 с после канал держит последнее значение |
| 2 — КЗ / занижение | `R < 0.1·R0` для RTD-типов (для режимов сопротивления не проверяется) |
| 3 — АЦП не отвечает | обратное чтение регистра 0 не совпадает с записанным |
| 4 — обратное включение | `code ≤ −0x10000` (−0.5 % шкалы): ток возбуждения не течёт S+ → S− — перепутаны S+/S−, датчик подключён между S− и E, нет обратного пути через E |

Ошибка выставляется после **3 подряд** ошибочных сканов и снимается (канал снова
`valid`) после 3 подряд нормальных — одиночный сбой не дёргает флаги и светодиод.
Двухпроводный датчик подключается между **S+ и E**, перемычка **S−–E**.

## Калибровка

Каждый канал калибруется отдельно для каждого класса усиления по 2-точечной
(или многоточечной) линейной модели:

```
R_true = gain × R_raw + offset
```

где `R_raw = code/2^23 × 2·RREF_ном / gain_PGA`. Коэффициенты хранятся per
channel × per class (20 слотов).

Калибровка выполняется поверенным магазином сопротивлений **АКИП-2202А
(0.05 %)** по Modbus TCP с помощью инструмента в `tools/` (Node.js или
Python, диалоговый режим). Подробности — в [tools/README.md](tools/README.md).

### Одноразовая запись (write-once)

Калибровка хранится в отдельном секторе Flash (sector 11), который прошивка
**никогда не стирает** в обычной работе — она переживает factory reset. Каждый
из 20 слотов (4 канала × 5 классов) можно зафиксировать (commit) **ровно один
раз**; после этого перезапись отклоняется. Порядок:

1. записать `gain`/`offset` в регистры `540+` — это живой предпросмотр
   (влияет на показания сразу, но не сохраняется);
2. записать `0xCA00 | (ch×5 + class)` в регистр `131` (**CAL COMMIT**) — слот
   программируется во Flash и блокируется. `slot = ch×5 + class`: `0` = CH0
   класс 0, … `4` = CH0 класс 4, `5` = CH1 класс 0, … `19` = CH3 класс 4;
3. статус блокировок — input-регистры `127` (биты 0..15) и `128` (биты 16..19).

Попытка записи в `540+` или повторного commit для уже заблокированного слота
возвращает Modbus-исключение `ILLEGAL DATA VALUE`.

### Аварийный сброс калибровки (двухфакторный)

Ошибочно откалиброванное изделие можно разблокировать, но только при
**физическом присутствии** (по сети в одиночку — нельзя):

1. записать `0xC1A5` в регистр `132` (**CAL ERASE ARM**) — взводит окно 30 с;
2. в течение окна удержать кнопку `FACT_RES` ~3 с.

Тогда сектор калибровки стирается (все слоты → `gain=1.0, offset=0.0`,
разблокированы), и модуль перезагружается. Во время взвода `STAT_LED` мигает
частым 5-импульсным поездом; перед перезагрузкой — быстрым равномерным
миганием. Одного взвода по сети или одного нажатия кнопки недостаточно.

## Карта регистров Modbus

Числа с плавающей точкой — IEEE-754 float32 в двух регистрах, **старшее слово
первым** (big-endian word order). Многоканальные величины сгруппированы **по
величине**: 4 регистра (или 4 пары) подряд — каналы 0..3.

### Компактный блок — Holding Registers (FC03/06/16), 0..27

| Рег | Описание |
|---|---|
| 0..3 | **показание, int16 (RO)**: RTD — температура °C × 100 (−327.68…+327.67); режимы сопротивления — 0..32767 от полной шкалы режима (200 / 2000 Ом); канал выключен — `0`; ошибка / нет достоверного отсчёта — `−32768` (`0x8000`) |
| 4..7 | тип датчика (`rtd_type_t`, 0..20) |
| 8..11 | enabled (0/1) |
| 12..15 | режим α (0 = стандартный, 1 = custom) |
| 16..19 | custom W100 × 10000 |
| 20..23 | форс класса усиления (0 = авто, 1..5 = класс 0..4; runtime, не сохраняется) |
| 24..27 | сглаживание (0 = выкл, 1 = слабое, 2 = среднее, 3 = сильное) |

Одним запросом `FC03 0..27` читается полное состояние всех каналов.

### Показания — Input Registers (FC04), 300..339

| Рег | Тип | Описание |
|---|---|---|
| 300..307 | float32 ×4 | температура, °C (NaN для режима сопротивления/ошибки) |
| 308..315 | float32 ×4 | калиброванное сопротивление, Ω |
| 316..323 | float32 ×4 | «сырое» сопротивление, Ω (вход калибровки) |
| 324..327 | u16 ×4 | флаги: bit0 enabled, bit1 valid, bit2 fault, bits15..8 = код ошибки (1 обрыв, 2 КЗ, 3 АЦП, 4 обратное включение) |
| 328..335 | int32 ×4 | 24-битный код АЦП со знаком (старшее слово первым) |
| 336..339 | u16 ×4 | активный класс усиления (0..4) |

Глобальные: `120` fw major, `121` fw minor, `122/123` uptime (с), `125`
module id (`0x04D1`), `126` температура MCU (signed 0.1 °C), `127`/`128`
битовая маска блокировки калибровки (бит `ch×5+class`).

### Общие настройки — Holding Registers (FC03/06/16)

| Рег | Описание |
|---|---|
| 100 | период опроса RTD, мс (50..5000) |
| 101 | режим LED (0/1/2) |
| 102 | Modbus slave id | 103 | Modbus TCP порт |
| 104..107 | static IP | 108..111 | netmask | 112..115 | gateway |
| 116 | net mode: `0` static / `1` DHCP / `2` link-local (default `2`) |
| 117 | SAVE (`0xA5A5`) | 118 | REBOOT (`0xB00B`) / BOOTLOADER (`0xB007`) / сброс KSZ8863 (`0x8863`) |
| 119 | FACTORY RESET (`0xDEAD`) | 130 | температура MCU (RO) |
| 131 | CAL COMMIT (`0xCA00 \| slot`, slot 0..19) — фиксация калибровки |
| 132 | CAL ERASE ARM (`0xC1A5`) — взвод аварийного сброса калибровки |

Коэффициенты калибровки (float32), база `540 + ch×20` (**write-once**):

| Смещение | Описание |
|---|---|
| + class×4 + 0..1 | gain, класс `class` (0..4) |
| + class×4 + 2..3 | offset, класс `class` |

Запись в эти регистры — живой предпросмотр; фиксация во Flash выполняется
записью `0xCA00 | (ch×5+class)` в регистр `131`.

Номинальный опорный резистор (float32, Ω): `620..621` (по умолчанию 2000.0).

## Программное сглаживание показаний

Помимо цифрового FIR-фильтра 50/60 Гц в `ADS1220`, прошивка имеет поканальный
программный фильтр — экспоненциальное сглаживание (EMA), включаемый
регистром `24 + ch`:

| Значение | Режим | Коэффициент α |
|---|---|---|
| 0 | выключено (по умолчанию) | — |
| 1 | слабое | 1/4 |
| 2 | среднее | 1/8 |
| 3 | сильное | 1/16 |

Фильтр применяется к калиброванному сопротивлению перед преобразованием в
температуру: `R = R + α·(R_изм − R)`. «Сырое» сопротивление (316..323) и код
АЦП (328..335) не фильтруются — по ним всегда видно нефильтрованный сигнал.

Фильтр автоматически перезапускается (заполняется первым же достоверным
отсчётом, без «доезда» от старого значения) после ошибки датчика, смены
класса/типа и любого изменения конфигурации канала.

**Важно: при включённом сглаживании период оцифровки аналогового сигнала
(регистр `100`) не равен времени установления показаний.** Каждый цикл опроса
показание обновляется, но после скачка измеряемой величины оно приближается к
новому значению экспоненциально. Ожидаемое время установления показания RTD:

```
t_уст(63 %) ≈ T_скан / α
t_уст(95 %) ≈ 3 · T_скан / α
```

где `T_скан` — период опроса (регистр `100`, мс), `α` — коэффициент из таблицы.

Примеры при `T_скан = 250 мс` (по умолчанию):

| Режим | α | t_уст(63 %) | t_уст(95 %) |
|---|---|---|---|
| слабое | 1/4 | ~1 с | ~3 с |
| среднее | 1/8 | ~2 с | ~6 с |
| сильное | 1/16 | ~4 с | ~12 с |

Увеличение периода опроса пропорционально растягивает время установления:
при `T_скан = 1000 мс` и сильном сглаживании `t_уст(95 %) ≈ 48 с`.
Настройка сохраняется по триггеру SAVE (регистр `117`) вместе с остальной
конфигурацией.

АЦП работает на 20 SPS: при периоде опроса меньше 50 мс соседние отсчёты
могут повторяться.

## Flash layout

Приложение собирается как образ для работы с bootloader.

| Область | Адрес | Размер | Назначение |
|---|---:|---:|---|
| Bootloader | `0x08000000` | 128 KB | sectors 0-4 |
| Metadata | `0x08020000` | 128 KB | sector 5 |
| Application | `0x08040000` | 256 KB | sectors 6-7 (эта прошивка) |
| Staging | `0x08080000` | 256 KB | sectors 8-9 |
| Settings | `0x080C0000` | 128 KB | sector 10 |
| Calibration | `0x080E0000` | 128 KB | sector 11 (write-once, не стирается) |

Настройки защищены CRC32; при несовпадении magic/version/CRC загружаются
дефолты. `SETTINGS_MAGIC = 0x04D14A57`, `SETTINGS_VERSION = 3` (HW2.1: новые
коды типов 19/20 и семантика форса класса; раскладка не менялась).

Калибровка хранится в секторе 11 как 20 CRC-защищённых слотов
(`ch×5+class`, magic `0xCA11B005`); сектор стирается только аварийным сбросом
(см. «Калибровка»). Пустой слот даёт нейтральные коэффициенты
`gain=1.0, offset=0.0`.

## Сборка

Требуется STM32CubeCLT (`starm-clang`, `cmake`, `ninja`).

```powershell
cmake --preset Debug
cmake --build --preset Debug
```

Идентичность варианта — единый источник `Application/fw_header/fw_header.h`:
`FW_PRODUCT_ID=0x504C0403`, `FW_HW_REVISION=0x0201`, `FW_VERSION_VALUE=0x020A`
(при необходимости переопределяются через `-DFW_PRODUCT_ID=...` и т.д.).
OTA принимает образ при совпадении product_id и старшего байта hw_revision —
образы HW1.x (`0x01xx`) и HW2.x (`0x02xx`) взаимно несовместимы.

Результаты: `.elf`, `.hex`, `.bin` в `build/Debug/`. `.bin` — OTA-образ с
`fw_header_t` по смещению `0x200`.

## Прошивка

```powershell
STM32_Programmer_CLI -c port=SWD -w build/Debug/PLCJS_ETH_MODULE_4RTD_D4MG_STM32F407VGT6.elf -v -rst
```

## Инструменты

`tools/calibrate.mjs` (Node.js 18+) и `tools/calibrate.py` (Python 3.8+) —
диалоговая калибровка и конфигурирование по Modbus TCP. См.
[tools/README.md](tools/README.md).

```powershell
node tools/calibrate.mjs status --ip 192.168.1.10
node tools/calibrate.mjs calibrate --ch 0 --class 1
python tools/calibrate.py set --ch 0 --type Pt100 --enable 1
```

## Примечания по точности

- Ток возбуждения 500 мкА: выходное напряжение IDAC `0.5 мА·R + 2.0 В` должно
  оставаться ниже `AVDD − 0.9 В ≈ 4.1 В`, т.е. `R ≲ 4200 Ом` — Pt1000 при
  850 °C (3905 Ом) укладывается.
- У `ADS1220` есть встроенный датчик температуры, но он не используется
  (режим TS отключает измерение входа); доступна температура MCU
  (`ADC1_IN16`, рег. 126/130).
