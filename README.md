Ethernet-модуль с четырьмя входами для измерения температуры датчиками
сопротивления и передачи показаний в PLC, SCADA или HMI по **Modbus TCP**.
Тип датчика, включение и сглаживание задаются отдельно для каждого канала.
Можно одновременно подключить, например, Pt1000, Pt100, 50П и 100П.

- **Модель:** PLCJS ETH 4RTD / D4MG
- **Аппаратная версия:** HW2.1 — STM32F407VGT6, четыре ADS1220
- **Версия приложения:** 2.10 (`0x020A`)
- **Каналы:** CH0…CH3; клеммы каждого канала — `S+`, `S−`, `E`.

> Все адреса регистров ниже — **нулевые адреса протокола Modbus**.
> `HR` — Holding Registers, `IR` — Input Registers. Учитывайте смещение,
> если SCADA/HMI использует обозначения `3xxxx`/`4xxxx` с единицы.
> Название «Кан.1» в интерфейсе ModbusTool соответствует CH0 на плате.

## 1. Назначение и основные возможности

Модуль предназначен для распределённого контроля температуры оборудования,
трубопроводов, ёмкостей и помещений. Он измеряет входные сигналы, но не
выполняет самостоятельно регулирование и не заменяет контроллер или
сертифицированное устройство аварийной защиты.

- Четыре отдельных 24-битных Δ-Σ АЦП ADS1220 — по одному на канал.
- Платиновые, медные и никелевые термосопротивления; полный список кодов — ниже.
- Трёхпроводное подключение с компенсацией сопротивления проводов;
  двухпроводное — с перемычкой и учётом сопротивления линии.
- Температура и сопротивление в float32, компактное показание int16,
  нефильтрованный код АЦП и поканальные диагностические флаги.
- Обнаружение обрыва петли, заниженного сопротивления, отрицательного
  сигнала и отсутствия ответа АЦП.
- Два внешних Ethernet-порта встроенного коммутатора KSZ8863.
- До четырёх одновременных Modbus TCP-клиентов.
- Обнаружение по MAC, назначение IPv4, статическая адресация, DHCP и link-local.
- Сохранение настроек во Flash, аппаратный watchdog, сброс настроек и OTA.
- Отдельная калибровка каждого канала и класса усиления, сохраняемая при
  обычном сбросе настроек.

## 2. Пользовательские характеристики

| Параметр | Значение / особенность |
|---|---|
| Количество измерительных каналов | 4, CH0…CH3 |
| Основная схема подключения | 3-проводная, два источника тока на канал |
| Ток возбуждения | Номинально 500 мкА на каждый IDAC; через датчик в штатной схеме течёт один ток |
| Опорный резистор | 2 кОм ±0.1 %, в цепи возврата обоих токов |
| Преобразование АЦП | 24 бита, 20 преобразований/с на канал, FIR с подавлением 50/60 Гц |
| Период программного опроса | 50…5000 мс, заводское значение 250 мс (`HR100`) |
| Сглаживание | Поканальное EMA: выключено, 1/4, 1/8, 1/16 |
| Режимы измерения сопротивления | 0…200 Ом и 0…2000 Ом |
| Программные шкалы температуры | Платина −200…+850 °C; медь −180…+200 °C; никель −60…+250 °C |
| Основной формат показаний | float32, °C или Ом; два регистра, старшее слово первым |
| Компактный формат температуры | int16, 0.01 °C на единицу; для полного температурного диапазона используйте float32 |
| Заводская конфигурация входов | Все включены, Pt1000, стандартный W100, сглаживание выключено |
| Изоляция | Измерительная часть отделена от MCU цифровым изоляционным барьером; наличие отдельного АЦП не означает межканальную развязку |
| Ethernet | KSZ8863, два внешних порта; передача трафика через коммутатор при включённом питании |
| Modbus TCP | Порт 502, Unit ID 1 по умолчанию; FC03, FC04, FC06, FC16 |
| Одновременные клиенты | До 4; при заполнении слотов новый клиент вытесняет дольше всех молчавшего |
| Обнаружение | PLCJS Discovery Protocol (PDP), UDP broadcast, порт 20556 |
| Дополнительная диагностика | Температура кристалла MCU, время работы, версия, состояние калибровки |

**Разрешение не равно точности.** 24 бита АЦП и отображение сотых долей градуса
не являются гарантией абсолютной погрешности. Она зависит от датчика, проводов,
контактов, опорного резистора, согласования токов и калибровки. Рабочий диапазон
конкретного датчика может быть уже программной шкалы.

Электрическая полная шкала также ограничена усилением и допустимыми напряжениями
аналогового тракта. Напряжение питания изделия, допустимые условия среды,
габариты и испытательное напряжение изоляции следует уточнять по документации
конкретного исполнения; параметры другого модуля семейства к 4RTD автоматически
не относятся. Схема платы: [PDF в DOC](DOC/PLCJS_ETH_MODULE_4RTD_D4MG_STM32F407VGT6.pdf).

## 3. Подключение датчиков

Подключайте по маркировке канала: `0S+ / 0S− / 0E` относятся к CH0,
`1S+ / 1S− / 1E` — к CH1 и т. д. Клемма **E — возврат измерительного тока**
через опорный резистор, не защитное заземление PE и не клемма экрана.
На RTD-входы нельзя подавать внешнее питание 24 В или сигнал 4–20 мА.

### Трёхпроводный датчик

```text
S+ ───────────────[ RTD ]─────┬──────── S−
                             └──────── E
```

Один провод идёт от одного вывода чувствительного элемента к S+.
Два отдельных провода от другого вывода идут к S− и E; **дополнительная
перемычка S−–E на модуле не нужна**. Определяйте пару по паспорту датчика,
а не только по цвету изоляции.

Компенсация предполагает близкие сопротивления проводов S+ и S− и согласованные
токи IDAC. Используйте одинаковые длину и сечение, надёжные контакты.
Прокладывайте измерительные линии отдельно от силовых проводов и источников
помех; экран подключайте по проекту заземления установки.

### Двухпроводный датчик или пассивный эталон

```text
S+ ───────────────[ RTD / R ]───────── E
S− ────────────── перемычка ───────── E
```

Датчик включается между S+ и E, на клеммах модуля ставится перемычка S−–E.
В этом варианте сопротивление соединительных проводов и контактов входит в
результат: для точного измерения предпочтительна трёхпроводная схема.
Сопротивление мультиметром измеряйте только на отключённой от модуля цепи,
без тока возбуждения от ADS1220.

## 4. Быстрый запуск

1. Подключите питание и Ethernet согласно схеме изделия, затем датчики.
2. Откройте ModbusTool, вкладку **«Обнаружение»**, выберите нужный сетевой адаптер.
   Заводской адрес модуля — link-local `169.254.x.y`, а не фиксированный `.12`.
3. Найдите модуль по MAC и назначьте уникальный рабочий адрес или DHCP.
   Для PDP разрешите входящий UDP/20556 в брандмауэре. При прямом обращении
   к link-local настройте соответствующую адресацию/маршрут на ПК.
4. Во вкладке **«Онлайн»** выберите карту **4RTD**, адрес модуля, порт `502`,
   Unit ID `1`. Непрерывное чтение можно начать с периода 500 мс.
5. Для каждого канала задайте тип в `HR4…7` по таблице ниже, включение в
   `HR8…11`; для неиспользуемых входов запишите `0` в регистр включения.
   После заводского сброса все входы включены как Pt1000 — неподключённые
   входы будут показывать ошибку.
6. Дождитесь завершения начальной проверки входов. Читайте не только
   температуру, но и `IR324…327`: для использования показания нужны
   `enabled=1`, `valid=1`, `fault=0`.
7. После настройки нажмите **SAVE** либо запишите `42405` (`0xA5A5`) в `HR117`.
   Без SAVE изменения обычных настроек потеряются при перезапуске.

Пример типов для четырёх разных датчиков:

| Канал | Датчик | Регистр типа | Значение | Регистр включения |
|---|---|---|---|---|
| CH0 | Pt1000 | HR4 | 18 | HR8 = 1 |
| CH1 | 50П | HR5 | 2 | HR9 = 1 |
| CH2 | Pt100 | HR6 | 8 | HR10 = 1 |
| CH3 | 100П | HR7 | 7 | HR11 = 1 |

Это пример конфигурации, не заводские настройки. Не меняйте тип на основании
похожего сопротивления: Pt100 и 100П имеют разные характеристики R(T).

## 5. Выбор типа датчика и диапазона

### 5.1 Коды типов (`HR4 + ch`)

R0 — сопротивление при 0 °C. W100 = R(100 °C)/R0; стандартное значение
выбирается по типу датчика.

| Код | Тип | Материал / характеристика | R0, Ом | W100 | Класс усиления |
|---|---|---|---:|---:|---:|
| 0 | 50М | Медь, ГОСТ | 50 | 1.4280 | 0 |
| 1 | Cu50 | Медь | 50 | 1.4260 | 0 |
| 2 | 50П | Платина, ГОСТ | 50 | 1.3910 | 0 |
| 3 | Pt50 | Платина, IEC 60751 | 50 | 1.3851 | 0 |
| 4 | Ni100 | Никель, DIN 43760 | 100 | 1.6180 | 1 |
| 5 | 100М | Медь, ГОСТ | 100 | 1.4280 | 1 |
| 6 | Cu100 | Медь | 100 | 1.4260 | 1 |
| 7 | 100П | Платина, ГОСТ | 100 | 1.3910 | 1 |
| 8 | Pt100 | Платина, IEC 60751 | 100 | 1.3851 | 1 |
| 9 | Ni500 | Никель, DIN 43760 | 500 | 1.6180 | 2 |
| 10 | 500М | Медь, ГОСТ | 500 | 1.4280 | 2 |
| 11 | Cu500 | Медь | 500 | 1.4260 | 2 |
| 12 | 500П | Платина, ГОСТ | 500 | 1.3910 | 2 |
| 13 | Pt500 | Платина, IEC 60751 | 500 | 1.3851 | 2 |
| 14 | Ni1000 | Никель, DIN 43760 | 1000 | 1.6180 | 3 |
| 15 | 1000М | Медь, ГОСТ | 1000 | 1.4280 | 3 |
| 16 | Cu1000 | Медь | 1000 | 1.4260 | 3 |
| 17 | 1000П | Платина, ГОСТ | 1000 | 1.3910 | 3 |
| 18 | Pt1000 | Платина, IEC 60751 | 1000 | 1.3851 | 3 |
| 19 | R200 | Сопротивление 0…200 Ом | — | — | 1 |
| 20 | R2k | Сопротивление 0…2000 Ом | — | — | 4 |

В режиме стандартной характеристики `HR12 + ch = 0`. Для нестандартного
датчика можно задать `HR12 + ch = 1` и W100 × 10000 в `HR16 + ch`
(например, `13851` для W100 = 1.3851). Это настройка характеристики датчика,
**не замена электрической калибровки канала**.

Для платины применяется модель Каллендара–Ван Дюзена, меди — линейная модель
с поправкой ниже 0 °C, никеля — полином DIN. При пользовательском W100
изменяется α, остальные коэффициенты соответствующей модели сохраняются.
За пределами программной шкалы преобразование температуры ограничивает
результат её границами; граничная температура сама по себе не доказывает
исправность подключения.

### 5.2 Автоматический выбор усиления

| Класс | Усиление PGA | Расчётная полная шкала АЦП | Применение |
|---|---:|---:|---|
| 0 | 16 | 250 Ом | Датчики с R0 = 50 Ом |
| 1 | 8 | 500 Ом | Датчики с R0 = 100 Ом и R200 |
| 2 | 2 | 2000 Ом | Датчики с R0 = 500 Ом |
| 3 | 1 | 4000 Ом | Датчики с R0 = 1000 Ом |
| 4 | 1 | 4000 Ом | Режим R2k |

Класс выбирается автоматически по типу. `HR20…23 = 0` — штатный режим;
`1…5` принудительно выбирают класс 0…4 для калибровки, действуют только до
перезапуска. При принудительном классе температура не выдаётся (NaN).
Классы 3 и 4 имеют одинаковое усиление, но **разные слоты калибровки**.

Полная шкала АЦП — не гарантированный диапазон всех датчиков. Нужно учитывать
запас до насыщения, допустимое напряжение IDAC и PGA. При номинальной опоре
2 В напряжение S+ составляет примерно `2 В + 0.5 мА × R`; увеличение тока
или сопротивления уменьшает запас по питанию аналогового тракта.

## 6. Обновление показаний и диагностика

### 6.1 Период опроса и достоверность

`HR100` задаёт период чтения АЦП прошивкой, **не частоту преобразования самого
ADS1220**: она остаётся 20 SPS. Более частый опрос Modbus не ускоряет измерение.

- После включения канала показания не считаются достоверными до первой
  проверки петли и завершения установления.
- Прошивка по очереди переключает каналы в монитор опорного напряжения для
  обнаружения обрыва. Во время проверки и последующего установления
  сохраняется предыдущее показание и статус; при штатном периоде 250 мс
  пауза обновления проверяемого канала составляет порядка 1 с.
- Интервал повторной проверки задан как 4 с, но проверки последовательные
  и привязаны к циклу задачи. Это **не гарантия обнаружения любого обрыва
  за 4 с**; задержка зависит от числа включённых каналов и `HR100`.
- При большом `HR100` начальная готовность, обнаружение обрыва и восстановление
  существенно замедляются. Флаг `valid` не является меткой времени нового отсчёта.
- Для прикладной логики проверяйте успешность сетевого чтения и флаги канала.
  Не используйте последнее число после потери связи как актуальное измерение.

### 6.2 Сглаживание (`HR24 + ch`)

| Значение | Режим | Коэффициент EMA |
|---|---|---|
| 0 | Выключено, заводская настройка | — |
| 1 | Слабое | 1/4 |
| 2 | Среднее | 1/8 |
| 3 | Сильное | 1/16 |

Фильтр применяется к калиброванному сопротивлению перед переводом в температуру:
`R = R + α × (R_изм − R)`. Сырое сопротивление `IR316…323` и код АЦП
`IR328…335` остаются нефильтрованными. После изменения конфигурации или ошибки
EMA инициализируется заново.

Оценка времени установления: `t63 ≈ T_скан / α`, `t95 ≈ 3 × T_скан / α`.
При 250 мс для слабого/среднего/сильного сглаживания это примерно 3/6/12 с
до 95 %. Паузы диагностики увеличивают фактическое время; эти оценки не
являются гарантированным временем реакции.

### 6.3 Флаги и ошибки (`IR324 + ch`)

| Поле | Значение |
|---|---|
| bit 0 | Канал включён (`enabled`) |
| bit 1 | Показание достоверно (`valid`) |
| bit 2 | Подтверждена ошибка (`fault`) |
| bits 15…8 | Код ошибки из таблицы ниже |

| Код | Значение | Что проверить |
|---|---|---|
| 0 | Нет подтверждённой ошибки | Дополнительно проверить `valid`; канал может ещё устанавливаться |
| 1 | Обрыв петли / превышение шкалы | Все три провода, перемычку двухпроводного подключения, диапазон датчика |
| 2 | КЗ / слишком малое сопротивление | Замыкание клемм и правильность типа; порог для RTD — `R < 0.1 × R0` |
| 3 | АЦП не отвечает ожидаемой конфигурацией | Питание измерительной части, SPI и выбор чипа; диагностика платы |
| 4 | Значительный отрицательный сигнал | Порядок S+/S−, цепь E; код не доказывает одну конкретную причину неисправности |

Обрыв определяется по снижению напряжения на RREF примерно ниже 0.4 В
и дополнительно по положительному насыщению (`code ≥ 0x7FF000`).
Код 4 соответствует `code ≤ −0x10000` — около −0.78 % положительной полной
шкалы АЦП. Для режимов сопротивления проверка «КЗ» отключена, поскольку 0 Ом
является допустимым значением.

Ошибки по коду подтверждаются после трёх последовательных ошибочных сканов;
до подтверждения может удерживаться последнее хорошее показание. Вердикт
монитора обрыва обрабатывается отдельно. После нормализации сигнала действует
окно установления перед возвратом `valid`; не считайте восстановлением только
исчезновение `fault` или изменение светодиода.

### 6.4 Светодиодная индикация

**Канальные светодиоды:**

| Индикация | Значение |
|---|---|
| Не горит | Канал выключен |
| Горит постоянно | Канал включён, нет подтверждённой ошибки; готовность отсчёта смотрите по `valid` |
| Плавно разгорается и гаснет | Ошибка: 1 с разгорание → 1 с затухание → 0.5 с темнота; полный цикл 2.5 с |

**STAT_LED** при `HR101 = 2` (заводской режим):

| Индикация | Значение |
|---|---|
| Одна вспышка в цикле 3 с | Ethernet-линк есть, свежих запросов Modbus нет |
| Две вспышки в цикле 1.5 с | Недавний запрос Modbus; учитывается и разовый запрос, не только постоянный сокет |
| Три вспышки в цикле 3 с | Нет линка на обоих внешних портах |
| Серия из пяти вспышек | Взведён аварийный сброс калибровки |
| Быстрое мигание по команде поиска | Идентификация выбранного модуля через PDP |

`HR101 = 0` выключает обычную индикацию STAT_LED, `1` включает постоянное
свечение. Служебная индикация сброса имеет приоритет. В загрузчике действуют
его собственные режимы: в bootloader v1.7 ожидание команды — плавное
разгорание/затухание с периодом 1 с.

## 7. Сеть и сохранение настроек

| Параметр | Заводское значение |
|---|---|
| Сетевой режим (`HR116`) | 2 — link-local |
| Адрес | `169.254.<mac[4]>.<mac[5]>`, маска `255.255.0.0` |
| Резервные поля static | `192.168.1.10`, маска `255.255.255.0`, шлюз `192.168.1.1` |
| Modbus TCP | Порт 502, Unit ID 1 |
| MAC | Локально администрируемый, формируется из 96-битного UID STM32 |

Адрес **192.168.1.12** используется на стенде как назначенный адрес 4RTD,
но не является заводским адресом прошивки. В одной сети каждому модулю
нужен отдельный IPv4. MAC приложения и загрузчика совпадает; их текущие
IP-настройки могут различаться, поэтому после перехода в загрузчик используйте
повторное обнаружение по MAC.

`HR116`: `0` — static, `1` — DHCP, `2` — link-local. После изменения сетевых
регистров выполните SAVE; сеть применяется без обязательной перезагрузки,
существующее соединение при смене IP может оборваться.

Обычные настройки каналов применяются в RAM. **SAVE (`HR117 = 42405`)**
сохраняет их во Flash вместе с сетевыми параметрами. Не записывайте SAVE
циклически с каждым опросом. Фиксация калибровки — отдельная команда, не SAVE.

При проблемах со связью:

- проверьте питание, линк, IP, маску, Unit ID и фактический маршрут через
  нужный Ethernet-адаптер;
- для поиска проверьте UDP/20556 и локальный широковещательный сегмент;
- VPN/TUN может перехватывать локальный трафик, особенно при обрыве кабеля;
  само открытие TCP-сокета на ПК ещё не доказывает ответ модуля;
- учитывайте лимит четырёх клиентов и отключение молчащего клиента через 30 с;
  используйте переподключение при ошибке транспорта;
- размещайте Modbus TCP в доверенной сети: протокол не предоставляет
  аутентификацию оператора для сервисных записей.

## 8. Карта регистров Modbus TCP

FC03 — чтение HR, FC04 — чтение IR, FC06/FC16 — запись HR.
Величины сгруппированы **по назначению**, затем по CH0…CH3.
Float32 — IEEE-754, два регистра, **старшее слово первым**; для int32 кода
АЦП порядок такой же. Для температуры CH0, например, читаются IR300 и IR301.

### 8.1 Настройки и компактное показание каналов

| HR | Доступ | Назначение |
|---|---|---|
| 0…3 | RO | RTD: температура ×100 как int16; R200/R2k: 0…32767 от шкалы 200/2000 Ом |
| 4…7 | RW | Тип датчика, код 0…20 |
| 8…11 | RW | Включение: 0/1 |
| 12…15 | RW | Характеристика: 0 стандартная, 1 пользовательский W100 |
| 16…19 | RW | W100 ×10000 для пользовательской характеристики |
| 20…23 | RW | Принудительный класс: 0 авто, 1…5 → класс 0…4; не сохраняется |
| 24…27 | RW | Сглаживание: 0…3 |

`FC03`, адрес 0, количество 28 — чтение всего компактного блока.
В HR0…3 выключенный канал возвращает `0`, ошибка или отсутствие достоверного
показания — `−32768` (`0x8000`). Остальные значения ограничиваются
−32767…32767: температура выше +327.67 °C здесь не помещается, используйте
IR300…307. В режимах сопротивления компактное показание ограничивается шкалой
режима; для результата в омах используйте float32.

### 8.2 Измерения и состояние

| IR | Формат | Назначение |
|---|---|---|
| 300…307 | float32 ×4 | Температура, °C |
| 308…315 | float32 ×4 | Калиброванное сопротивление, Ом |
| 316…323 | float32 ×4 | Сырое сопротивление, Ом; используется при калибровке |
| 324…327 | u16 ×4 | Флаги состояния и код ошибки |
| 328…335 | int32 ×4 | Знаковый 24-битный код АЦП |
| 336…339 | u16 ×4 | Активный класс усиления, 0…4 |
| 120 / 121 | u16 / u16 | Версия приложения: major / minor (2 / 10) |
| 122 / 123 | u16 / u16 | Время работы, секунды: **младшее / старшее** слово |
| 125 | u16 | Идентификатор модуля `0x04D1` |
| 126 | int16 | Температура MCU, 0.1 °C на единицу |
| 127 / 128 | u16 / u16 | Маска блокировок калибровки: биты 0…15 / 16…19 |

Температура равна NaN в режимах сопротивления, при принудительном классе
калибровки и при подтверждённой ошибке. NaN также используется для
недоступных измерений. Всегда проверяйте флаги независимо от значения float32.
Температура MCU служит внутренней диагностикой и не заменяет датчик окружающей среды.

### 8.3 Общие настройки

| HR | Доступ | Назначение |
|---|---|---|
| 100 | RW | Период программного опроса, 50…5000 мс |
| 101 | RW | STAT_LED: 0 выкл., 1 вкл., 2 автоматическая индикация |
| 102 | RW | Modbus Unit ID |
| 103 | RW | TCP-порт Modbus |
| 104…107 | RW | Четыре октета статического IPv4 |
| 108…111 | RW | Четыре октета маски |
| 112…115 | RW | Четыре октета шлюза |
| 116 | RW | Режим сети: 0 static / 1 DHCP / 2 link-local |
| 130 | RO | Температура MCU (int16, 0.1 °C), как IR126 |
| 620…621 | RW | Номинальный RREF, float32 в омах; по умолчанию 2000.0 |

### 8.4 Сервисные команды

В ModbusTool можно пользоваться кнопками у строк команд либо вводить число
вручную. Для hex нужен префикс `0x`; десятичные значения приведены отдельно.
Команды отправляйте однократно, а не циклически.

| HR | Команда | Hex | Decimal | Действие |
|---|---|---|---:|---|
| 117 | SAVE | `0xA5A5` | 42405 | Сохранить обычные настройки |
| 118 | REBOOT | `0xB00B` | 45067 | Перезапустить приложение |
| 118 | BOOT | `0xB007` | 45063 | Перейти в Ethernet bootloader |
| 118 | KSZ RESET | `0x8863` | 34915 | Сбросить коммутатор; временно нарушает связь через оба порта |
| 119 | FACTORY RESET | `0xDEAD` | 57005 | Сбросить настройки и перезапустить модуль |
| 131 | CAL COMMIT | `0xCA00 \| slot` | 51712 + slot | Необратимо зафиксировать слот калибровки, slot 0…19 |
| 132 | CAL ERASE ARM | `0xC1A5` | 49573 | Взвести окно физического подтверждения стирания калибровки |

Обычный factory reset **не стирает калибровку**, но возвращает link-local,
включённые каналы и тип Pt1000. Аппаратный способ: удерживать `FACT_RES`
при старте модуля не менее 2 с; сброс сопровождается служебной индикацией.

## 9. Калибровка и метрологические особенности

Каждый канал калибруется отдельно для каждого класса усиления: всего
**20 слотов (4 × 5)**. Модель линейная:

```text
R_cal = gain × R_raw + offset
slot = ch × 5 + class
```

Две разнесённые точки определяют gain/offset; третья и последующие позволяют
проверить линейность и выполнить МНК. Они не устраняют систематическую
погрешность самого эталона.

Используйте пассивные прецизионные резисторы, поверенный магазин сопротивлений
или измеренные эталоны с известной неопределённостью. Для активного RTD-симулятора
сначала проверьте допустимый ток возбуждения, схему подключения и совместимость
с входом модуля. Паспортная точность **воспроизведения** сопротивления не равна
точности его **измерения**; одного совпадения на одной точке недостаточно.

Для точной работы учитывайте провода, контакты, ТКС и саморазогрев. При
трёхпроводном подключении оба возвратных провода должны соединяться у эталона;
компенсация требует близких сопротивлений проводов S+ и S−. Не принимайте
сопротивление проводов двухпроводной оснастки за постоянную ошибку модуля.

### Коэффициенты и предпросмотр

База регистров: `540 + ch × 20 + class × 4`.

| Смещение от базы | Формат | Значение |
|---|---|---|
| +0…1 | float32 | gain |
| +2…3 | float32 | offset, Ом |

Для незаблокированного слота запись — **предпросмотр в RAM**. Сначала соберите
сырые показания `IR316…323` с корректным классом и `valid=1`, вычислите
коэффициенты, проверьте независимую контрольную точку. Во время диагностики
петли показания удерживаются: повторное чтение одного числа не обязательно
является новым независимым отсчётом.

Не меняйте RREF после калибровки: это меняет пересчёт сырого кода и делает
ранее найденные коэффициенты неприменимыми.

### Фиксация и аварийное стирание

1. После проверки запишите `51712 + slot` в `HR131` только по осознанному
   решению оператора: слот программируется во Flash **один раз** и блокируется.
2. Проверяйте блокировку по `IR127/128`, бит `ch × 5 + class`.
3. Повторный commit или изменение коэффициентов заблокированного слота
   отклоняется с `ILLEGAL DATA VALUE`. SAVE не заменяет CAL COMMIT.

Аварийное стирание удаляет **все 20 слотов**, не один выбранный:
записать `49573` в `HR132`, затем в течение 30 с удерживать `FACT_RES`
около 3 с. Модуль стирает калибровку и перезапускается. Нейтральные
коэффициенты после стирания — gain = 1, offset = 0. Одного взвода по сети
или одного нажатия кнопки недостаточно. Обычные SAVE и FACTORY RESET сектор
калибровки не стирают.

Инструменты: [tools/README.md](tools/README.md), `tools/calibrate.mjs`
(Node.js 18+) и `tools/calibrate.py` (Python 3.8+). Адрес `.12` ниже — пример
для модуля с уже назначенным статическим адресом:

```powershell
node tools/calibrate.mjs status --ip 192.168.1.12
node tools/calibrate.mjs calibrate --ch 0 --class 3 --ip 192.168.1.12
python tools/calibrate.py set --ch 0 --type Pt1000 --enable 1 --ip 192.168.1.12
```

## 10. Обновление прошивки

Для HW2.1 нужен загрузчик варианта **4rtd** и приложение для **ADS1220**.
Прошивки HW1.x (MAX31865 + ADG849) несовместимы; исторический вариант
сохранён тегом `hw1.1-last`.

При штатном OTA через ModbusTool выберите модуль по MAC, переведите его в
bootloader командой BOOT и загрузите соответствующий `.bin`. Во время
обновления обеспечьте стабильное питание, не отправляйте параллельно команды
сброса или сохранения. После запуска проверьте IR120/121 и состояния каналов.

Загрузчик проверяет product_id и старшую часть аппаратной ревизии.
Первоначальная установка или обновление самого загрузчика выполняется по
ST-Link; загрузчик и приложение занимают разные области Flash. Полное
стирание MCU удаляет в том числе настройки и калибровку — для обычного
обновления приложения оно не требуется.

## 11. Справочник разработчика

### 11.1 Аппаратная платформа и распиновка HW2.1

MCU — STM32F407VGT6 (Cortex-M4F), Ethernet — KSZ8863, четыре ADS1220,
внутренний датчик температуры MCU (`ADC1_IN16`), watchdog IWDG.

| Сигнал | Пин | Сигнал | Пин |
|---|---|---|---|
| SPI1 SCLK | PA5 | SPI1 MISO | PA6 |
| SPI1 MOSI | PB5 | | |
| RTD0_CS | PC6 | RTD1_CS | PD15 |
| RTD2_CS | PD14 | RTD3_CS | PD13 |
| RTD0_STAT | PE14 | RTD1_STAT | PE13 |
| RTD2_STAT | PE12 | RTD3_STAT | PE11 |
| STAT_LED | PE9 | FACT_RES | PE10 |
| ETHRST | PD11 | ETHINT | PB1 |

SPI: master, 8 бит, MSB first, mode 1 (CPOL=0, CPHA=1), PCLK2/32 ≈ 2.6 МГц.
DRDY не разведён; задача читает последний результат командой RDATA.
Канальные LED используют программный ШИМ на TIM7, 64 уровня около 200 Гц;
форма затухания рассчитывается задачей индикации.

### 11.2 Измерительный тракт

```text
S+ → AIN2 (IDAC1); через 10 кОм → AIN0 (AINP)
S− → AIN3 (IDAC2); через 10 кОм → AIN1 (AINN)
E  → RREF 2 кОм → GND_ISO; REFP0/REFN0 подключены к концам RREF
```

| Регистр ADS1220 | Штатное значение | Назначение |
|---|---|---|
| 0 | `0x00 / 0x02 / 0x06 / 0x08` | MUX AIN0/AIN1, PGA 1 / 2 / 8 / 16 соответственно |
| 1 | `0x04` | 20 SPS, normal, continuous |
| 2 | `0x55` | Опора REF0, FIR 50/60 Гц, IDAC 500 мкА |
| 3 | `0x70` | IDAC1 → AIN2, IDAC2 → AIN3 |

При равных токах `V_REF = 2 × I × RREF`, и
`R_raw = code / 2^23 × 2 × RREF_nom / gain_PGA`. Отношение напряжений снижает
влияние общего изменения токов; их рассогласование, допуск RREF и ошибка PGA
остаются источниками погрешности.

Проверка петли временно выбирает MUX `(REFP0−REFN0)/4`. В этом режиме ADS1220
использует внутреннюю опору для преобразования монитора; биты VREF остаются
REF0, выбирая измеряемую пару. Встроенный датчик температуры ADS1220 в штатных
измерениях не используется.

### 11.3 Память и идентичность

| Область | Адрес | Размер | Сектора |
|---|---|---|---|
| Bootloader | `0x08000000` | 128 КБ | 0…4 |
| Metadata | `0x08020000` | 128 КБ | 5 |
| Application | `0x08040000` | 256 КБ | 6…7 |
| Staging | `0x08080000` | 256 КБ | 8…9 |
| Settings | `0x080C0000` | 128 КБ | 10 |
| Calibration | `0x080E0000` | 128 КБ | 11 |

Настройки защищены CRC32: `SETTINGS_MAGIC = 0x04D14A57`, `SETTINGS_VERSION = 3`.
При невалидных данных загружаются заводские настройки. Калибровка — 20
CRC-защищённых слотов, magic `0xCA11B005`; пустые слоты дают gain = 1 и offset = 0.
Сектор 11 занят калибровкой и не должен использоваться для staging.

Идентичность в [fw_header.h](Application/fw_header/fw_header.h):
`FW_PRODUCT_ID=0x504C0403`, `FW_HW_REVISION=0x0201`, `FW_VERSION_VALUE=0x020A`.
Заголовок `fw_header_t` находится по смещению `0x200` образа. Linker размещает
приложение с `0x08040000` и резервирует верхние 16 байт RAM под запрос загрузчика.

### 11.4 Сборка и загрузка через ST-Link

Требуются STM32CubeCLT (`starm-clang`), CMake и Ninja. Сборка из корня репозитория:

```powershell
cmake --preset Debug
cmake --build --preset Debug
cmake --preset Release
cmake --build --preset Release
```

Артефакты `.elf`, `.hex`, `.bin`, `.map` находятся в `build/Debug/` или
`build/Release/`. `.bin` используется для OTA. Приложение рассчитано на запуск
через загрузчик, установленный отдельно.

```powershell
STM32_Programmer_CLI -c port=SWD -w build/Debug/PLCJS_ETH_MODULE_4RTD_D4MG_STM32F407VGT6.elf -v -rst
```

Архитектура, ограничения Flash и правила изменения общих подсистем описаны
в [AGENTS.md](AGENTS.md). Англоязычная документация — [README_EN.md](README_EN.md).
